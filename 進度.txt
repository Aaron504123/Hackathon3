# 無障礙導航專案：目前進度與詳細目標

更新日期：2026-10-09

## 一、專案摘要

本專案的目標是建立一個服務香港輪椅使用者、長者及行動不便人士的無障礙步行導航原型。使用者輸入起點和終點地點後，系統搜尋地點座標、建立步行路線、分析沿線地形坡度，並在地圖上展示可取得的無障礙設施資料。

目前已完成可運作的前後端原型，重點是證明「地點搜尋 → 路線取得 → DEM 坡度分析 → 設施標記 → 地圖呈現」的資料流程。現階段結果是輔助參考，不是經認證的無障礙路線，也不能保證路線不含樓梯。

## 二、問題與服務對象

目標使用者包括輪椅使用者、長者，以及因傷病或其他原因而行動不便的人士。使用者在出發前可能難以確認路線坡度、樓梯、升降機和無障礙廁所等資訊；資料分散或不完整時，途中遇到障礙會增加行程風險及對照顧者的依賴。

本專案希望把路線和可取得的通行資訊放在同一個介面，讓使用者能在出發前看見風險，而不是把系統結果誤當作「一定可通行」的保證。

## 三、詳細目標

### 目前 MVP 目標

1. 讓使用者輸入香港的起點與終點地點名稱，而非要求手動輸入經緯度。
2. 將地點名稱轉成座標，並拒絕超出目前香港座標範圍的搜尋結果。
3. 取得步行路線，並在地圖上顯示路線、起點、終點及沿線設施。
4. 依本地 DEM 高程資料估算坡度，使用顏色協助使用者辨認不同坡度級別。
5. 顯示最大坡度與設施數量等摘要資訊，並在手機螢幕上維持可操作的版面。
6. 在資料不足、外部服務失效或路線使用直線備援時，清楚處理錯誤及限制，避免誤導使用者。

### 下一階段的無障礙目標

1. 優先提供避開樓梯的路線，並在 OSM 有可靠資料且路網確實連接時，使用升降機連接不同樓層。
2. 清楚標示路線是否經過已標記的樓梯、升降機或其他通行障礙，並說明資料來源。
3. 改善坡度估算，使其更接近道路或行人路實際坡度，而不只反映周邊地形格網。
4. 提供替代路線及可理解的風險比較，而不是只返回單一路線。
5. 與輪椅使用者及長者進行實地路線驗證和介面易用性測試。

### 長期目標

1. 在資料可取得的前提下，加入升降機運作狀態、臨時障礙及設施維修資訊。
2. 建立障礙回報和資料更新流程，並提供資料來源、更新時間及可信程度。
3. 依據實際使用者需求建立可解釋的路線評估方式；在完成驗證前，不宣稱分數代表已認證的無障礙程度。
4. 持續改善色彩對比、觸控尺寸、文字可讀性及其他行動裝置無障礙設計。

## 四、目前系統架構

- **前端：**React 19、Vite、Mapbox GL JS；主要程式在 `frontend/src/App.jsx`，樣式在 `frontend/src/App.css`。
- **地點搜尋：**Photon／OpenStreetMap 地理編碼服務；前端搜尋結果會套用香港經緯度矩形範圍檢查。
- **路線服務：**Flask `POST /route` 優先呼叫 ORS wheelchair；ORS 無可用路線時改用 Mapbox Directions `walking`，兩者都失敗才使用直線備援。
- **地形分析：**Rasterio 讀取香港 DEM GeoTIFF；PyProj 轉換座標，GeographicLib 計算距離與坡度。
- **設施資料：**Barrier Free Map `/api/items` 提供無障礙廁所及傷殘人士泊車位；OpenStreetMap Overpass 提供樓梯、升降機、斜坡等其他障礙資料。
- **前後端連線：**Vite 將 `/api` 代理至 Flask 的 `localhost:5000`。

## 七、目前限制與風險

### 電梯與樓梯導航

- Mapbox Directions walking profile 沒有避開樓梯或優先使用升降機的參數。
- 曾對截圖中的路線要求 Mapbox alternatives，但服務只回傳一條路線，因此目前後端不能保證挑選到無樓梯路線。
- OSM 雖可標示 `highway=steps`、升降機等資料，但資料可能不完整；升降機位置存在也不代表它已被正確連接到可通行路網。
- 已接入 OpenRouteService wheelchair profile，使用 `avoid_features: ["steps"]` 及坡度限制；「九龍塘站 → 楊建文學術樓」測試時 ORS 回報兩點間沒有可用 wheelchair route，系統改以一般步行次級路線處理。即使 ORS 有路線，能否經由特定升降機仍取決於 OSM 樓層連接資料。

### 坡度可信度

- DEM 是 5 公尺格網地形資料，不是行人路表面測量；可能無法表達樓梯、天橋、建築物、擋土牆、路緣或實際平坦路面。
- 20 公尺平滑會減少格網雜訊，但可能模糊短距離的陡坡或樓梯；部分路段仍可能出現不符合實際路面的高坡度估算。
- 最大坡度是所有分段絕對角度中的最大值，下降也會被視為陡坡；單一高值可能主導摘要。

### 外部資料服務

- Barrier Free Map API key 已設定於後端；實測 `/api/items` 回 HTTP 200。API 資料可用不代表每條路線附近都有設施。
- 本地 PBF 索引有效時，OSM 障礙查詢不依賴 Overpass；索引缺失、過期或讀取失敗時才 fallback Overpass，屆時仍可能遇到 504 並缺少 OSM 標記。
- 地點搜尋、Mapbox 路線和底圖都依賴網路與有效 token。

### 範圍及備援

- 香港範圍檢查使用經緯度矩形近似，不是精確的香港土地邊界。
- ORS 無法提供 wheelchair route 時，Mapbox Walking 是一般步行次級路線，不保證輪椅可通行；前端會顯示此限制。
- ORS 與 Mapbox 都失敗時的直線備援不能當成導航路線；前端會明確提示此路徑不是可行走道路。
- 目前只計算及顯示一條選定路線，尚無完整的多路線比較或經使用者研究驗證的無障礙評分。

## 九、成功評估指標

- 地點搜尋：起終點是否能穩定定位到使用者指定的香港地標。
- 路線：是否可重現、是否避開已知樓梯，以及無可用路線時是否明確告知。
- 電梯：選定路線是否真的連接到 OSM 標記的升降機及其上下層通行路徑，而非只經過附近座標。
- 坡度：與實測值的差距、平路誤報率及陡坡漏報率。
- 設施：資料覆蓋、位置正確度、資料來源和更新狀態。
- 效能：路線計算時間及外部 API 失敗時的回復行為。
- 易用性：目標使用者完成指定旅程所需時間、錯誤率及對資訊的信心。

## 十、專案定位提醒

目前成果是可展示地點搜尋、Mapbox 步行路線、DEM 坡度估算和設施標記的原型。除非完成輪椅專用路由、電梯連接驗證及實地使用者測試，否則不應宣稱系統已能保證無樓梯、必經電梯或提供已認證的無障礙路線。
